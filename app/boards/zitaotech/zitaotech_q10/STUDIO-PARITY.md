# Q10 / Sofle Studio 对比（2026-10-28）

参考：Sofle README 指定的 V1.08 左手配置（left.conf、unified-test.conf、
unified-left.conf），并对照本机 modular-sofle-left 的编译配置。
Q10 为单体键盘，设备名称保持 `ZitaoTech_Q10`，四个设备槽位。

## 已有功能

Q10 已开启 Studio USB/BLE、动态键位、宏、组合键、动态踢踏、默认层、
OS 识别、蓝牙管理、休眠设置、设备信息、矩阵测试、Bootmagic、触控板和背光 RPC。
这些功能使用与 Sofle 相同的 app / feature module 实现。
USB UART 发送 FIFO 满时退出循环、RPC 编码错误释放互斥锁的修复也是共享的。
Q10 的 RPC RX/TX 缓冲分别为 192/512 字节，自定义请求容量 192 字节；
无需照搬 Sofle 的 256/256/128 设置来缩小已有容量。

## 本次补齐

| 项目 | Q10 原配置/行为 | 本次修改 |
| --- | --- | --- |
| USB Studio 串口关闭 | UART_LINE_CTRL 未开启，RPC 不执行 DTR 检查 | 开启，复用已有的 DTR 发送检查 |
| 输入线程 | 优先级 0，栈 1024 | 优先级 9，栈 2048，与参考 Sofle 一致 |
| BLE HID 线程 | 优先级 5 | 优先级 9，与参考 Sofle 一致 |
| 主机连接参数 | 间隔 6–12，latency 30 | 请求间隔 6（7.5ms）、latency 0、timeout 400（4s） |
| BLE Studio 活跃时 latency | 10 | 0，避免 Studio 再将请求的 latency 提高 |
| 连接参数恢复 | 未进入 Sofle 的 host tuner 分支 | Q10 复用该逻辑；参数尝试至多三次，间隔至少五秒 |
| 连接对象回收 | 未进入 Sofle 的 recycled 分支 | 回收后重新调度广播更新 |
| 加密 | 未开启 GATT 自动安全请求 | 开启；主机 tuner 同时复用 L2 安全请求 |
| 配对事务 | 普通分支 | 复用 Sofle 的成功后提交、失败/取消清理、跨槽位重复拒绝和连接引用释放 |
| 设置查找 | 无 NVS 查找缓存 | 使用 512 项缓存 |
| I2C 等待 | 默认配置 | 100ms 超时，与 Sofle 一致 |

蓝牙间隔由主机最终协商，固件请求不保证所有电脑都接受。
Sofle 的配对替换分支本身标为 experimental；复用不等于已经实机验证。
四槽位都占满时更换设备可在 Studio 清除选定槽位后配对，不增加第五槽位。

## 保留的 Q10 差异

- BT_MAX_CONN=4、BT_MAX_PAIRED=4，非分体，最终 BLE_PROFILE_COUNT=4。
- 不加入 Sofle 的右手、接收器、第二蓝牙身份、屏幕或旋钮功能。
- 不复制 Sofle 为自定义图片准备的 32 个 NVS 扇区；Q10 保持原来 8 个，
  分区地址、大小及 NVS 几何均未调整，避免引入设置迁移。
- 保留 Q10 矩阵、触控板、LED 接线以及现有键位。
- 保留本次已确定的默认触控板参数：DPI30、曲线开启，6 / 1.48 / 0.66 / 1.35。
- 保持已有 Just Works 和允许重新配对配置，不启用密码输入。
